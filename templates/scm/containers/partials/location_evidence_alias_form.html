The reported name and code travel in hidden fields so the alias that gets stored is the string the resolver will actually compare. There is no "create the location" here. A canonical location is master data somebody should mean to add, and the queue links to the ordinary location form for a place that genuinely is not in the network yet. On success the view answers with HX-Redirect back to the queue, so the operator lands on a freshly built page with this row resolved. An error — a duplicate alias is the usual one — re-renders this modal with its messages. {% endcomment %}
