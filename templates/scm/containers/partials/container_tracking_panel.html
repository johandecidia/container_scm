{% load i18n %} {% comment %} Carrier tracking for one container, in the two places the workspace shows it: the current-state summary on Overview and the journey timeline on Journey. This template owns both, so there is one description of a container's tracking and one refresh behind it. `containers:refresh_tracking` renders this template with no `panel_section`, which produces:
… swapped into the Overview summary
… swapped into the Journey tab One request, one carrier call, both tabs current. The refresh button and the Actions menu both target `#container-tracking-panel`; nothing targets the timeline directly, so it cannot be refreshed on its own and drift. The workspace page includes this template twice, once per tab, naming the section it wants — the tab wrappers own visibility, so neither swapped element carries Alpine state that a swap could lose.
