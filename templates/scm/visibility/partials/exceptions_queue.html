{% load i18n %} {% comment %} The Exceptions work queue: the count, the filters and the rows. Swapped whole by HTMX whenever a filter changes, which is why the count is in here and not in the page header — it describes the current selection. Layout: one row per object, as a grid that reflows. Dense and table-like from `sm` up, stacked into a readable card below it. One set of markup rather than two, so a column added on desktop cannot go missing on a phone — and no horizontal scroll, which is not an operational mobile experience. There is no acknowledge, assign, resolve or snooze. None of that state exists in the database, and a button that only looked like it did would misrepresent the platform. A row leaves this queue when the supply chain changes. {% endcomment %} {% url 'visibility:exceptions' as queue_url %}
