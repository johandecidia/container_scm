The same markup for both statuses because the row is the same shape and the action is the same action; only the reason differs, and the reason is what the two headers say. A row is a decision, not an event. Repeated evidence — one provider, one reported name, one reported code — is grouped, so a carrier that has said "GOTHENBURG" four hundred times is one line of work. The event count is how much evidence is currently unattached, not a severity. Ambiguous rows carry the resolver's own candidate list: the places it could not choose between. They are shown and not chosen from automatically, which is the point — a port and a terminal inside it legitimately share a UN/LOCODE, and picking one on the operator's behalf is exactly the confidently-wrong answer the resolver refuses to give. Recording an alias changes what the *next* resolution decides. It does not rewrite the events already stored, and this section says so rather than leaving somebody to wonder why the row is still here. {% endcomment %}
