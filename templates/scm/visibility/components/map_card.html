{% load i18n %} {% comment %} The one map component. Included by the Control Tower, the shipment detail page, the container detail page and the location workspace; the differences are the mode, the GeoJSON URL and the height. Usage: {% include "scm/visibility/components/map_card.html" with map_title=_("Supply Chain Map") map_height="h-[28rem]" %} Reads from context: mapbox, map_mode, map_data_url. Optional: map_title, map_height, map_panel_target, map_note, map_card_class (the surrounding panel style, so a dense page can ask for a tighter one), operational_map (LOC-4's read model, for the filters and the coverage line). The legend is the honest part of the map. Three position classes mean three different things and are told apart by shape as well as colour — a filled disc, a hollow diamond, a hollow square — because colour alone excludes readers who cannot distinguish it and dies in a printout. The shapes are drawn in map.js and mirrored here as characters, so the key and the map say the same thing. Without a Mapbox token the card renders a configuration notice and the rest of the page — queues, timeline, ETA, tracking state — carries on working. The map is an enhancement, and a missing token must never take a page down with it. {% endcomment %}

"Show destinations" is off by default and is a second question, not more of the first: destination markers say where inbound volume is heading, and counting them as current positions is the error this map exists to avoid.
